# Phase 2 report

## Implemented

- Added persisted `agent_runs` records with goal, selected domains, mode, trace and recommendations.
- Added a bounded Supervisor that routes to energy, maintenance and inventory specialists.
- Added deterministic specialist analyses using Phase 1 domain helpers and household records.
- Added `POST /api/agents/runs` and `GET /api/agents/runs/{run_id}`.
- Added a dashboard action showing mock mode, recommendations and the node trace.
- Added invalid-domain and persistence regression tests.

## Verification

- Backend: `11 passed, 3 warnings` with `cd backend; python -m pytest tests -q`.
- Frontend: `npm run build --prefix frontend` passed. Vite emitted its existing non-blocking bundle-size advisory.
- Live API: passed on a clean SQLite database for health, empty analysis, seeded analysis, run persistence, invalid domains and missing runs.
- Live browser: passed for empty analysis, demo seeding, populated analysis, charts, recommendation cards and visible Supervisor-to-specialist trace.

## Not tested or incomplete

- Live Gemini integration was not tested because no API key or model was provided.
- LangGraph and Gemini provider packages are not installed; Phase 2 currently uses a deterministic mock-safe orchestration implementation.
- No autonomous database writes are performed by specialists.
- Telegram, vision, scheduling, n8n and deployment remain out of scope.

## Known limitations

- Agent runs are stored as completed records; streaming, cancellation and retry handling are not implemented.
- Recommendation text is deterministic and not generated by an LLM in the default mode.
- FastAPI still emits the existing startup-hook deprecation warning.

## Credentials and manual actions

- Keep `LLM_MODE=mock` for the verified local path.
- Supply `GEMINI_API_KEY` and `GEMINI_MODEL` before enabling a future live provider.

## Status

The bounded mock-safe Phase 2 foundation is implemented and locally verified. Live LLM execution remains blocked pending credentials and provider setup.
